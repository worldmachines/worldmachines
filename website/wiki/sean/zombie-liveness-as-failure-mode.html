Zombie liveness as a failure mode

Sean · updated 7 September 2026 · source on GitHub
The Liveness Machine's characteristic failure isn't collapse or overload but false animacy — mistaking simulated responsiveness for the real thing, keeping something twitching that's already dead, which is what engagement-optimized feeds and content slop amount to once tending has replaced maintenance as the operative verb.

The idea

Each register in the machine sequence has its own signature way of failing through over-maintenance rather than neglect. The Modernity Machine rationalizes itself to death, stripping out the tacit know-how that was actually holding the system together in the name of legibility. The Divergence Machine drowns in coordination overhead, each diverged world quietly pushing its upkeep costs onto the others. The Liveness Machine's failure is different in kind from both: it's seduced by false animacy.

Where the modernity failure is too much rationalization and the divergence failure is too little shared coordination, the liveness failure is a category confusion — treating something as alive because it responds, without asking whether the responsiveness reflects anything that can be harmed, cared for, or actually answers back. Engagement-optimized feeds and low-effort content are the clearest instance: they twitch convincingly, and the twitching is mistaken for life. Because tending only makes sense where there's something alive to tend, this failure mode is specific to registers where liveness has become the operative currency — it doesn't have an equivalent in a register organized around inherited frames or around patched-together coordination, because those registers were never claiming to be alive in the first place.

Grounding

Part of a larger register-by-register failure-mode synthesis, built alongside the maintainable/patchable/tendable sequence. The Modernity Machine failure mode it's contrasted against draws on two separate accounts — Tainter's on over-rationalization and Scott's on legibility stripping out tacit know-how; the zombie-liveness diagnosis itself — false animacy as the Liveness Machine's characteristic failure — is original, not drawn from a named source.

How settled this is

That Tainter and Scott each describe part of the Modernity Machine's failure mode this way, in their own separate books, is checkable against those books directly. That the Liveness Machine has a comparably structured, opposite-in-kind failure mode is this note's own claim, offered because it matches what's visible in current engagement-driven platforms, not because it's been checked against a wider literature on liveness or animacy.

Connections

  • maintainable-patchable-tendable — the sequence that makes tending, and therefore false-tending, a coherent category in the first place
  • dawn-day-dusk-pathologies — a related typology of pathologies across the machine sequence that this failure mode should be checked against

Open

Is there a reliable way to tell false animacy from the real thing from the inside — some test a tender could apply in the moment — or is the diagnosis only ever available in hindsight, once the thing being tended has already turned out to have been dead?
